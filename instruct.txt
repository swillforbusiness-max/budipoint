# PROJECT: BUDIPOINT – DIGITAL SERVICES AND FINTECH PLATFORM

## 1. PROJECT OVERVIEW

I want to build a modern, professional, scalable digital services platform called **Budipoint**.

Budipoint will allow registered customers to access and purchase various digital products and services from one platform.

The platform must have two distinct environments:

1. Customer/User Dashboard.
2. Administrator Dashboard.

The application must be developed using a modular, API-first architecture. The backend will expose REST APIs, while the frontend will communicate with these APIs through a centralized API service layer.

IMPORTANT: I will provide the actual third-party API credentials, documentation and endpoints later. Therefore, build the application in a way that makes future API integration straightforward. Do not invent live API integrations or pretend that transactions have been completed.

For the initial development, use realistic mock data and clearly distinguish simulated operations from real transactions.

## 3. BRAND IDENTITY AND DESIGN SYSTEM

The design must look like a premium, modern fintech and digital services platform.

Use the following brand colours consistently:

Primary red: #FC5050
Dark navy: #111D30
Background: A clean off-white shade such as #F8F9FB.
White: #FFFFFF.
Body text: #111D30.
Secondary text: A suitable muted grey.

Design direction:

- Clean and spacious layouts.
- Modern typography.
- Professional fintech dashboard appearance.
- Rounded cards with controlled border radii.
- Subtle shadows.
- Thin borders.
- Clear visual hierarchy.
- Consistent spacing.
- Attractive buttons and input fields.
- Smooth hover effects.
- Carefully designed empty states.
- Consistent loading indicators.

Use #FC5050 for primary buttons, active states and important highlights.

Use #111D30 for navigation, headings, dashboard elements and important text.

Avoid excessive gradients, unnecessary glassmorphism and overly decorative effects.

### Animation requirements

Use Framer Motion for:
- Page transitions.
- Dropdown animations.
- Modal transitions.
- Sidebar interactions.
- Card entrance animations.
- Button feedback.
- Small interface transitions.

Use GSAP selectively for:
- Homepage hero animations.
- Subtle background movement.
- Scroll-triggered animations.
- Special promotional sections.

Do not use both animation libraries for the same element.

All animations must be smooth, purposeful and performance-conscious.

Respect reduced-motion accessibility preferences.

### Icon requirements

Use pure SVG icons only.

Create a reusable SVG icon component system with consistent:
- Stroke width.
- Dimensions.
- ViewBox.
- Stroke colour.
- Active and inactive states.

Do not use emojis, Unicode symbols as icons, icon fonts, or external icon libraries.

## 7. API-FIRST ARCHITECTURE

This is one of the most important requirements.

The application must be designed around a centralized API integration architecture.

On the React side, create:

src/
  api/
    client.ts
    auth.api.ts
    user.api.ts
    wallet.api.ts
    transaction.api.ts
    services.api.ts
    admin.api.ts

  services/
    auth.service.ts
    wallet.service.ts
    transaction.service.ts

  hooks/
    useAuth.ts
    useWallet.ts
    useTransactions.ts

  types/
    auth.types.ts
    user.types.ts
    wallet.types.ts
    transaction.types.ts
    service.types.ts

Create a centralized Axios client with:

- Base API URL.
- Authentication handling.
- Request interceptors.
- Response interceptors.
- Error handling.
- Consistent response handling.
- Environment-based configuration.

Use an environment variable for the API base URL.

Example:

VITE_API_BASE_URL=http://localhost:8000/api/v1

Do not scatter API URLs across React components.

All API communication must happen through the centralized API layer.

For the initial stage, implement mock repositories or mock API responses behind the same service interfaces. This will allow me to replace mock implementations with real API integrations later without rewriting the user interface.

5. Explain the purpose of important commands before running them.
